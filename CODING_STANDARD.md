# Our Coding Standard

## Code (product standard)
- We follow PEP 8
- Constants are UPPERCASE
- No magic numbers. No if nested more than 2 levels
- Code should be explained with a short comment describing what the code block does

## Git (process standard)
- Never commit directly to main.
- One new branch per Feature: feature/<short-name>
- Commit messages start with a Verb: Add, Fix, Update
- Merge into main only through a reviewed pull request
- All tests must pass before a PR is merged
